# Language House · 学生与教学平台

独立的学生管理 Web 应用，为 Lessonfold 提供学生、班级、课次和已确认学情，并归档发布讲义。使用 Node.js 24+ 内置 HTTP / SQLite / crypto，无运行时第三方依赖。本目录不会改写根目录的英语备课 Skill、知识库或 Word 生成器。

## 本版可用功能

- 管理员：建立稳定 ID 的学生档案、同名搜索、改名，开通/停用账号、重设密码，建立班级、分配老师、维护有效在班时间，排课/改排/取消、出勤及操作审计。
- 老师：查看授权班级和学生学习时间线，确认教材版本/册次/单元，记录逐个学生的实际表现，保存/编辑草稿，核对并确认学习证据，管理作业与复测。
- 学生：只查看当前在班且属于本人课次的已发布学生版材料和自己的出勤。API 不返回教师答案、班级名单或他人学习记录。
- Lessonfold：管理员核验账号绑定后，五分钟一次性入口码换取仅限一个课次的服务端委托；按需读取确认学情；校验并原子归档纯文本发布快照，重复请求返回原回执，内容冲突返回 409。
- SQLite 文件持久化；密码 scrypt 加盐；登录会话 HttpOnly / SameSite=Strict；写操作核对 Origin 和 CSRF；停用、交接班级、撤销/更换绑定均撤销已有委托。

课堂材料、出勤、课次状态和学习结论独立保存。归档讲义不会扣课时、自动完成课次或发送任何家长消息。没有接入模型时，也不会伪造 AI 输出。

## 本地运行

先安装 Node.js 24 或更新版本。从本目录执行，演示数据库必须为空：

```sh
node src/cli.js demo
node src/server.js
```

打开 `http://127.0.0.1:8787`。演示包含两个虚构学生、一个班级、连续两个课次、管理员 `admin`、老师 `teacher`、无授权老师 `teacher2` 和学生 `student`。初始化命令只输出一次随机演示密码，四个账号共用；首次登录后可在页面修改自己的密码。演示不预绑定任何 Lessonfold 账号。重复运行 `demo` 会拒绝覆盖数据。

首次正式使用时在**另一个空数据库**初始化管理员，用户名交互输入，密码随机生成：

```sh
PLATFORM_DB=data/production.sqlite node src/cli.js setup
PLATFORM_DB=data/production.sqlite node src/server.js
```

从“账号与连接”开通老师，从“学生档案”新增学生，建立班级并加入学生，然后安排课次。一对一课建立单人班级；外部协议在本实现中 `class_id` 必填。

从仓库根目录也可执行 `node student-platform/src/server.js`，但默认 `data/` 是相对于当前工作目录的路径。建议始终在本目录运行，或指定绝对 `PLATFORM_DB`。

## 复现教学闭环

1. 以 `teacher` 登录，打开第 1 次课的“课后记录”。学生甲已有已确认的 borrow/lend 记录；学生乙的写作表现仍为草稿。
2. 到第 2 次课的“备课学情”，仅能看到甲的已确认事实，以及双方未完成跟进。
3. 回到第 1 次课，核对并确认乙的记录，再刷新第 2 次课；乙的事实出现，学情版本变化。
4. 将作业或复测标记完成，下一次上下文不再列为未完成；“完成跟进”不会把错误结论改成已掌握。
5. 以 `student` 登录，第 1 次课可见演示学生讲义，教师答案与私人证据不会由接口返回。
6. 以 `teacher2` 登录，原班级/学生/课次均不可见。管理员改派班级后，新老师可接续历史，原老师即时失去访问和发布权限。

与外部 Lessonfold 的握手/归档可以运行 `node --test test/platform.test.js` 复现，测试使用真实临时 HTTP 服务模拟 Lessonfold 后端请求，包括入口消费、双重凭证、重复归档和权限撤销。实际账号绑定前，管理员须在双方系统确认账号控制权，不能只按同名猜测。

## 配置与部署

可复制 `.env.example` 为 `.env`，执行 `node --env-file=.env src/server.js`。不要提交 `.env`、数据库或生成密码。配置项：

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `PLATFORM_DB` | `data/platform.sqlite` | SQLite 文件，建议绝对路径 |
| `HOST` / `PORT` | `127.0.0.1` / `8787` | 后端监听地址和端口 |
| `PLATFORM_ORIGIN` | `http://127.0.0.1:8787` | 浏览器实际访问源，不能带路径或结尾 `/` |
| `LESSONFOLD_URL` | 空 | Lessonfold 备课入口；后端配置；生产使用 HTTPS |
| `LESSONFOLD_SERVICE_KEY` | 空 | 双方后端共享随机服务凭据，至少 32 字符 |

更换本地端口时也要同步 `PLATFORM_ORIGIN`。服务凭据可由 `node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"` 生成，通过部署系统秘密配置保存，不能写入浏览器、PR、URL或访问日志。未配置地址与凭据时“去备课”明确返回未配置状态，不影响其他管理功能。

正式部署要求 HTTPS 反向代理和进程守护；非回环监听必须设置 HTTPS `PLATFORM_ORIGIN`。应用校验 HTTPS Origin，但 TLS 由反向代理终止。代理禁止记录请求正文、查询串和身份凭据，限制请求大小及登录速率，并透传 Origin。应用不信任 `X-Forwarded-For`，代理部署下应用的登录限流按代理连接地址与用户名计算。单店使用单个进程、单机持久化磁盘；SQLite 不应放在网络共享盘或由多容器副本共享。

可用 `Dockerfile` 构建部署镜像：

```sh
docker build -t language-house-students .
docker volume create language-house-data
docker run --rm -it -v language-house-data:/app/data language-house-students node src/cli.js setup
docker run -d --name language-house-students --restart unless-stopped \
  -p 127.0.0.1:8787:8787 -v language-house-data:/app/data \
  --env-file /secure/path/student-platform.env language-house-students
```

环境文件需设置 `HOST=0.0.0.0` 和 `PLATFORM_ORIGIN=https://实际学生系统域名`，容器端口只暴露在本机，由 HTTPS 代理访问。容器以非 root 的 `node` 用户运行，使用绑定目录时先设置可写权限。镜像构建与生产部署需在目标环境验证，本 PR 的验证是本地 Node/SQLite 与浏览器，不声称已部署。

`GET /health` 只返回数据库连接状态，不暴露账号或学情。由部署系统探测健康并重启故障进程。备份前停止应用，复制整个 `data/`（包括 WAL/SHM），再启动；恢复时停服务替换数据目录。数据结构目前为首版 `schema.sql`；未来升级需新增显式迁移，不通过删除数据库升级。

## 权限与数据约定

| 操作 | 运营管理员 | 授课老师 | 学生 |
| --- | --- | --- | --- |
| 学生档案、账号、排课、班级分配 | 管理 | 读取自己班级；修改自己课次 | 本人课次 |
| 出勤 | 写入 | 写入 | 仅本人读取 |
| 学习事实、教师版材料 | 不返回事实/教师版 | 仅当前授权班级 | 不返回 |
| 学习结论确认、作业/复测 | 不允许 | 仅当前授权学生 | 不允许 |
| 跨系统账号绑定 | 线下核验后登记 | 使用已核验绑定 | 不允许 |

本版一个班级指定一个授课老师，交接整个班级会立即替换历史与未来课次的教学权限；课次里的 `teacher_id` 保留原排课来源，授权以班级当前老师为准。学生材料同时核验课次当时在班、当前在班和发布名单。名单快照不会因加入/退出而改写。教师可查看其当前班级历史材料，个人学习档案与上下文仅包含当前授权学生。学生退出仍保留后台历史，不向已退出账号开放。

姓名不作主键；时间存 UTC，页面固定北京时间。教材信息不完整或未经老师明确核验时保持待确认。未测评时分数必须为 `null`。学习证据一经老师确认不可直接覆盖，可新增更正记录。草稿、出勤、学生/班级/课次编辑使用版本校验；冲突返回 409，页面保留表单供老师核对。

近期上下文仅取目标课次之前、当前老师有权限的最近三次**有已确认记录的课次**，每名学生最多 30 条，截断显式标记 `history_truncated`；全部历史可在学生档案查看。未完成跟进按授权和课次时间筛选。上下文版本对可见进度、学生名单、确认事实和跟进内容做规范化摘要，生成时间不影响版本。观察文字属于数据，接入方不得将备注拼入系统指令。

## 接口、测试和边界

外部可执行约定、JSON Schema、OpenAPI、固定摘要测试向量和字段映射放在 [`../integration-contracts/`](../integration-contracts/README.md)。内部路由概览见 [API.md](API.md)。运行所有测试：

```sh
node --test test/*.test.js
```

CI 使用 Node 24，测试只创建临时数据库、虚构账号和回环 HTTP 服务，无需外部账号或模型密钥。

两份输入讨论稿依据的是另一个 Lessonfold 仓库，本仓库没有 `preparations`、D1 或备课前端。本版完整实现学生系统一侧；Lessonfold 侧仍需按协议实现入口消费、经核验的当前用户身份、备课关联保存、审核/陈旧结果校验、不可变快照与持久化同步重试。不能仅把 `LESSONFOLD_URL` 填上就宣称两边已联调。

本版只接收纯文本材料。共享文件托管、家长端、收费与课时账本、自动消息、完整多机构运营和 AI 生成/批改属于后续范围；不会把根目录旧 Skill 的邮件描述当作本平台的自动发送授权。
